# 把学习应用接入 CangHui

游戏化学习不等于需要游戏引擎。页面、题目、选项、反馈与结算可以直接组合普通 `chui` 控件；词库、计分、复习和语音仍由应用拥有。先跑通 [learning-flow](../../../examples/learning-flow/README.md)，再迁移产品，不必重写业务。

## 先划清边界

| 保留在应用 | 使用框架已有能力 |
|---|---|
| 词库、题型、判分、复习与存档 | `State`、布局和标准控件 |
| 产品配色、插图与内容授权 | 主题、字体注册与资源解析 |
| 语音合成、音频设备适配和播放状态 | UI 展示播放状态与触发应用动作 |
| 业务导航及完成条件 | 焦点、输入、窗口与动画 |

框架能力声明不等于平台实现。尤其不能把 AudioOutput 声明当作所有平台已经具有通用播放器；缺少音频时显示不可用状态，不伪造播放成功。

## 第一段迁移只做一个闭环

1. 建立迁移分支，保留旧版本作为回退，不同时运行两个 SDL 事件循环。
2. 从原渲染代码中提取判题与存档逻辑；先为重复提交、错误答案、重试、损坏存档补测试。
3. 用普通控件完成「进入 → 答题 → 反馈 → 结算 → 重试」。Button 用 `.key()` 维护稳定焦点身份；`.probe()` 或 `ProbeNode` 发布可观察事实。
4. 用 `prntx` 检查窄／宽视口和键盘操作，再用 `prnt` 检查字形、换行与视觉密度。不要用整张固定分辨率画面放大来替代布局。
5. 接入应用资源和语音，再迁移其他题型。旧宿主只能在完整替代验收后退出，不能提前删掉回退路径。

## 缩放与 Harmony 宿主

桌面可通过 `WindowSpec` 的 `WindowScaleSettings` 接入框架缩放。尺寸使用逻辑单位；不要在布局、窗口和触摸三个位置各乘一次 density。

Harmony 宿主必须依照 [输入坐标契约](../../reference/input-coordinates-and-dpi.zh-CN.md) 与 [provider SDK](../../reference/harmony-provider-sdk.zh-CN.md) 接线：保留坐标来源、尺度修订和 surface 生命周期；移动到新 DPI 后更新变换；取消事件不能假装为一次点击。原生回调应通过受控事件入口交给 UI 所在线程，不能并发直接改学习状态。

原生黑屏排查先确认：surface 已创建、渲染与窗口使用同一 SDL 实例、资源目录有效、尺寸／尺度已更新、暂停恢复与销毁没有留下旧句柄。不要为绕过宿主问题再复制一套框架渲染器。依赖必须来自锁定工具链或包，不从相邻应用的构建目录临时拷贝。

## 分开记录完成度

- 模型测试通过：只证明业务状态转换。
- `prntx` 通过：证明确定性布局与注入交互，不证明真机触摸。
- 桌面运行：记录版本、字体、窗口尺寸和输入路径。
- Harmony 运行：另附设备、签名产物、点击／取消、动态 DPI、前后台恢复和音频证据。
- 可分发：再核对资源授权、依赖来源、安装与干净环境启动。

只有这些证据覆盖实际产品流程，才能称为应用迁移完成；样例编译和无签名 HAP 都不能代替它。
