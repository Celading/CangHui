# 从可交互原型迁移到原生布局

[CangHui 指南](../../index.md) › 从原型迁移

原型适合确定产品语义，但不能把浏览器里的伪桌面、绝对定位和临时 DOM 直接
翻译成原生控件树。迁移时先冻结“同一视口下的产品外壳”，再逐层落实约束。

## 1. 先截原型，再写布局

用无头浏览器在与目标窗口相同的视口截取每一个产品状态，不要只看 CSS 数值：

- 固定窗口宽高、浏览器缩放和截图倍率；
- 标出头部、内容区、底栏和固定动作区的实际高度；
- 记录字号、行高、内边距、间距、圆角和边框；
- 同时截取正常数据、空结果、长文本和禁用状态。

如果原生截图是 3x，先按窗口逻辑尺寸归一化，再比较相对比例。只比较两张图的
像素数量会把缩放误判成布局差异。

## 2. 只迁移产品外壳

HTML 原型常带伪桌面、菜单栏、Dock、壁纸、装饰性浮层和演示抽屉。它们不是
产品窗口的职责。先列出“必须进入原生产品壳”的区域，例如：

```text
搜索框 / 结果列表 / 底栏 / 设置侧栏 / 预览区
```

其余原型装饰保留为设计参考，不为了截图相似而伪造第二套桌面。

## 3. 用模式数据，不用布局对象做“模态”

产品的模式切换应落在一个业务状态上：

```cangjie
let mode = State<LauncherMode>(LauncherMode.Quick)
```

根视图读取 `mode.value` 选择一个声明式分支。不要用 `Modal` 模拟搜索/详细/
设置等整窗模式，也不要保存已构建的布局对象再手工显隐。模式数据同时可以驱动
窗口尺寸、底栏选中态和标题。

## 4. 明确谁 hug，谁 flex

CangHui 的 `VStack` 和 `HStack` 默认参与父级弹性分配。内容卡片、工具条、
导航项和按钮行通常应先 `.hug()`，再 `.fillWidth()`：

```cangjie
VStack {
    Label("历史")
    historyRows()
}.hug().fillWidth()
```

只有真正应占剩余空间的主列表或编辑区使用 `.flex()`。如果一个窄按钮在截图里
变成整行，优先检查它是否处在未 `hug` 的 `HStack` 中。

## 5. 行高必须覆盖完整文本框

列表行不是“最大字号加一点 padding”。行盒至少需要容纳：

```text
标题行高 + 副标题行高 + 行间距 + 上下 padding
```

`LazyColumn.of(..., itemHeight)` 的槽位与行内容高度应成对设置。先预留整行，
再用 `prnt` 检查；不要把字号缩小当成布局修复。

`Label` 是表单文本控件，不是裸字形：单行测量至少为 28 vp，并额外保留 6 vp
行盒内衬。把两个 `Label` 直接放进 32/46 vp 的密集原型行时，文本会溢出或把
整行撑高。密集只读行应显式使用真实字体度量的小型文本叶子，让 `measure`
返回 `textWidth/textHeight`，并在绘制时按 `frame.centerY() - textHeight / 2`
居中；需要多行、省略或无障碍语义时仍优先使用 `Label`。

## 6. 图标按钮按几何中心验收

固定方形图标按钮不要依赖 `HStack` 的交叉轴对齐。默认交叉轴是 `Stretch`，
仅设置外层宽高并不能保证非拉伸图标位于几何中心。使用 `ZStack` 让图标在固定
方框内绝对居中，再把背景、边框和点击层继续包在同一个方框上：

```cangjie
ZStack {
    Icon(iconName).iconSize(14.vp)
}.width(27.vp).height(27.vp)
```

截图验收时同时检查按钮外框、图标笔画外接框和命中区三者中心一致；文字标签
按钮则按字体基线单独复核，不能拿同一个 `HStack` 规则硬套。

## 7. 对照截图闭环

每个模式至少保留一张原型参考图和一张原生运行图。验收顺序是：

1. 窗口尺寸和圆角一致；
2. 头部、内容、底栏占用比例一致；
3. 列宽/侧栏/预览区不互相挤压；
4. 长标题、长路径和空状态不裁切；
5. 鼠标和键盘操作不因视觉重排失效。

“颜色相似”不是布局完成。只有真实运行截图、可重放的尺寸参数和交互测试共同
通过，才能称为原型对齐。
